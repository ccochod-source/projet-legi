Projet Légi — comment marche le MCP

On donne une URL, une entreprise (nom ou SIREN) ou une question juridique : l'outil renvoie un rapport point par point, sourcé sur des API officielles, avec un indice /100.

« L'IA ne fait que choisir les outils et rédiger. Les faits viennent d'API officielles via le MCP, chaque affirmation est rattachée à une source vérifiée, et en cas de doute l'outil répond « à vérifier » au lieu d'inventer. »

1Architecture : qui parle à qui

2Déroulé d'une question

① Question
« Analyse le site https://exemple.fr »
② Session MCP
L'app récupère la liste des 4 outils
③ Groq
reçoit consigne système + question + outils
④ Choix
« appelle analyser_site(url) »
⑤ Exécution
Le MCP lit vraiment le site et applique les règles
⑥ Enchaînement
SIREN trouvé, article de loi… (≤ 3 tours, 6 appels)
⑦ Validation
Référence hors sources = rejetée ; statuts repris tels quels
⑧ Affichage
Tableau de bord /100 + détail ; historique Supabase

3Les 4 outils

rechercher_textes_loi
(question, fond="CODE_DATE", nb_resultats=5)
  • Codes (CODE_…) ou lois hors codes (LODA_…), version en vigueur
  • Titre, n° d'article, état, dates, extrait, lien legifrance.gouv.fr
  • Extraits marqués « non complets »
consulter_article
(article_id)
  • Texte complet d'un article LEGIARTI…
  • Refuse les textes entiers LEGITEXT…
  • Tronqué au-delà de 6 000 caractères
  • L'IA cite le vrai texte, pas sa mémoire
verifier_entreprise
(nom_ou_siren)
  • 5 entreprises max : SIREN, nom, active/cessée, création, activité, commune
  • Jamais les dirigeants ni l'adresse complète
  • 429 → 1 seul nouvel essai
  • Inscrite ≠ en règle
analyser_site
(url)
  • Accueil + liens légaux (mentions, confidentialité, cookies, CGV, CGU) → 6 pages max
  • Détecte traceurs (Google, Meta, Hotjar…), bandeaux cookies (Didomi, Axeptio…), vente en ligne, activité pro
  • Vérifie jusqu'à 2 SIREN
  • Évalue les 21 obligations
Format commun : {"statut":"ok", …, "sources":[{titre, reference, url, date_recuperation}]} ou {"statut":"erreur","erreur":"message clair"} — un outil ne fait jamais planter l'application.

5Le tableau de bord : l'indice /100

service-public.fr (example.com : 7/100)
Calcul déterministe — fait par le code, pas par l'IA

score = 100 × poids des points conformes / poids des points applicables

  • Poids : critique ×3 avertissement ×2 information ×1
  • conforme rapporte son poids ; manquant et à vérifier rapportent 0
  • non applicable est retiré du calcul (on ne pénalise pas un blog pour ses CGV)
  • Aucun point applicable → pas de score
Ce qu'affiche la page
  • Jauge colorée : rouge < 50, orange 50–79, vert ≥ 80
  • Sous-score par thème (mentions, RGPD, cookies, e-commerce, sécurité)
  • Cartes À corriger (triées par gravité, avec action concrète), À vérifier, Conformes, Non applicable
  • Tableau détaillé derrière « Voir le détail »
  • Mention : « Indice des éléments détectés automatiquement, pas un verdict juridique »

6Les garde-fous

Contre l'invention
  • L'IA ne touche jamais aux API
  • Référence acceptée seulement si renvoyée par un outil
  • Statuts du site non modifiables par l'IA
  • Contenus = données, jamais instructions (anti-injection)
  • Température 0, 1 200 jetons max
Lecture des sites
  • http/https vers adresses publiques seulement
  • Anti-SSRF : 127.0.0.1, 192.168.x, 169.254.169.254 refusés, à chaque redirection
  • 2 Mo, 5 redirections, 20 s, HTML seulement
  • Aucun contournement anti-robots
Données personnelles
  • Jamais de dirigeants ni d'adresse complète
  • Extraits de preuve ≤ 80 caractères
  • E-mails et téléphones masqués
  • Supabase : RLS, aucune règle publique
Robustesse
  • Légifrance : jeton en cache, 1 nouvel essai après 401, erreurs 400/401/403/404/429/5xx traduites
  • Groq : quota atteint → modèle de secours 20b
  • Résultats compactés
  • Échec Supabase → rapport quand même rendu

7Deux modes, mêmes outils

En local (Mac / Linux)
  • bash lancer.sh : Python ≥ 3.10, .venv, dépendances, demande des clés sans les afficher
  • L'app lance server.py en processus séparé, dialogue en stdio
  • Accessible seulement sur 127.0.0.1
  • Clés dans .env (permissions 600)
En ligne (Vercel)
  • Serverless = pas de 2ᵉ processus → transport MCP en mémoire (même protocole)
  • index.py + vercel.json (60 s)
  • Redéploiement automatique à chaque fusion dans main
  • Clés dans les variables chiffrées Vercel
Sécurité en ligne
  • En-tête X-Code-Acces obligatoire sur /api/, sinon 401
  • Comparaison hmac.compare_digest
  • Code gardé pour l'onglet (sessionStorage)
  • CSP stricte, no-store, nosniff, refus des requêtes d'un autre site
  • Aucune clé sur GitHub ni dans le zip

9Les limites (à assumer)

1. Pas un avocat« conforme » = élément détecté, pas validé juridiquement
2. HTML initial seulementpas de JavaScript : traceurs dynamiques et vrai comportement du bandeau non testés
3. 6 pages maxune info placée ailleurs n'est pas vue
4. Mots-clés et règlesformulation inhabituelle → « à vérifier », rarement un faux résultat
5. Périmètre limitéLCEN, RGPD, cookies, e-commerce de base ; pas RGAA, secteurs réglementés, droit étranger
6. Sites anti-robotsDecathlon, Leboncoin : 403, pas d'analyse, pas de contournement
7. Légifrance Sandboxenvironnement de test ; recherche libre parfois mal classée
8. Registreinscrit ≠ en règle ; homonymes possibles
9. Quotas Groq gratuits≈ 8 000 jetons/min : parfois quelques secondes d'attente
10. Questions libressynthèse de l'IA, parfois incomplète ; seules références et statuts sont verrouillés
11. En ligne50 s max, un seul code partagé, historique selon la table Supabase
Injection de prompten cas de manipulation, l'outil refuse de travailler plutôt que d'affirmer
